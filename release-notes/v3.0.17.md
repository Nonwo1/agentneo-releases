# AgentNEO v3.0.17 — Automatic Sandbox Provisioning & Health Centre

AgentNEO v3.0.17 completes the automatic-sandbox path introduced in v3.0.14–v3.0.16. When a prompt requires isolated execution, AgentNEO can now diagnose and prepare the Windows isolation backend itself instead of only reporting that no backend is ready.

## Sandbox Health Centre

- Adds a dedicated Health Centre inside Sandbox Lab with overall, Quick Windows Sandbox, Hyper-V Build Lab and restart/resume status indicators.
- Deep scan checks Windows edition/build/architecture, CPU virtualization, SLAT, firmware virtualization, hypervisor presence, Windows Sandbox/Hyper-V optional feature state, Hyper-V PowerShell/VM tooling, compatible switches, pending feature restart, free RAM and SandboxRoot free storage.
- Statuses distinguish READY, TESTING, CONFIGURING, RESTART REQUIRED, USER ACTION REQUIRED, DEGRADED, FAILED, NOT SUPPORTED and DISABLED instead of returning one generic setup error.
- Detailed information explains what failed, why it matters, whether AgentNEO can repair it and the next action.

## Automatic Safe provisioning

- `sandbox_auto_prepare` now invokes the backend provisioner when isolation is required and no verified backend is ready.
- In AUTOMATIC SAFE mode AgentNEO may launch a UAC-elevated request to enable supported Windows Sandbox/Hyper-V optional features on demand.
- Normal AgentNEO installation still does not silently enable virtualization features.
- UAC cancellation, unsupported Windows edition and Windows servicing failures are returned as explicit provisioning errors and do not permit host fallback.
- AgentNEO does not edit BIOS/UEFI settings. Firmware virtualization disabled in firmware becomes a precise USER ACTION REQUIRED condition with a shortcut to Windows firmware restart options.
- AgentNEO does not download/bundle Windows ISO/VHD/VHDX/WIM images. Persistent Hyper-V Build Lab still requires a user-provided VHDX and protected guest credentials.

## Real backend self-tests

- Windows Sandbox readiness can be verified by a real disposable `.wsb` launch that executes a task-scoped command, writes/reads mapped output and verifies cleanup.
- Hyper-V readiness can be verified through a disposable differencing VHDX VM, guest startup, PowerShell Direct command execution/file flow, checkpoint/restore and cleanup.
- Successful tests are cached for a configurable period to avoid paying the startup cost on every task.
- A failed real self-test is retried once to tolerate transient host pressure before the backend is declared failed.

## Restart & Resume

- When Windows feature changes require restart, AgentNEO stores the original prompt/run/sandbox decision under `SandboxRoot/PendingActions`.
- Sandbox Health Centre exposes Restart & Resume and Cancel Pending Resume controls.
- After restart, AgentNEO re-scans the host and verifies the backend before resubmitting the original prompt; it does not report success merely because the feature command returned successfully.
- Restart remains user initiated; AgentNEO does not force reboot without the explicit Restart & Resume action.

## Resource-aware sandbox allocation

- Adds AUTO/LIGHT/BALANCED/HIGH/CUSTOM resource modes.
- AUTO considers current CPU, available RAM and NVIDIA GPU/VRAM pressure when sizing a sandbox so a host already saturated by model inference is not unnecessarily starved.
- Preferred backend can be AUTO, Windows Sandbox or Hyper-V Build Lab.

## Preserved safeguards

- Isolation-required execution still never falls back to generated/test code on the host.
- The existing AgentNEO download broker remains the only automatic tool download path.
- Host folders/credentials remain scoped by the existing Sandbox Lab policies.
- v3.0.16 fast-task routing and progress-aware model timing remain unchanged.
- v3.0.15 shared-session autonomous orchestration, v3.0.14 Sandbox Lab, Media Studio, updater, PC Doctor, privacy, Whisper and Neural Galaxy behaviour remain preserved.
