# AgentNEO v3.0.16 — Fast Task Execution & Progress-Aware Orchestration

AgentNEO v3.0.16 is a focused orchestration-performance and correctness update driven by a real v3.0.15 sandbox test that spent hours in repeated 15-minute model waits despite the Sandbox Decision Engine having already determined in under a second that no compatible isolation backend was ready.

## Fast task execution

- Adds a deterministic low-complexity fast path for small sandbox execution/test tasks.
- Fast-path tasks skip Prompt Architect, Planner and Writer advisory calls and enter the Supervisor tool loop directly.
- Complex architecture, deep research, production, security-audit, refactor and codebase-wide tasks keep the full dependency-aware multi-agent graph.
- The fast path does not weaken verification: real sandbox command evidence is still required before a requested execution/test can be reported as successful.

## Progress-aware local model timing

- The old 900-second fixed request timeout is no longer the normal factory policy.
- Local model timeouts are treated as **lack-of-stream-progress watchdogs**, not total task deadlines.
- Warm resident local model: 240 seconds without streamed progress.
- Cold local model load: 360 seconds without streamed progress.
- High GPU/VRAM/RAM pressure: up to 480 seconds without streamed progress.
- Online/API response-stall default: 180 seconds.
- Every streamed Ollama chunk resets httpx's read timeout, so a healthy generation may continue far longer than these values while progress continues.
- Model progress events record stream chunk count, content growth and elapsed time.
- Factory retry counts are bounded to two attempts instead of allowing repeated dead waits to multiply into hours.

## GPU/resource efficiency

- Factory `resources.max_parallel_model_jobs` changes from 2 to 1.
- Factory `ollama_num_parallel` changes from 2 to 1.
- Existing installations are migrated only when they still contain the exact old factory value; deliberate user overrides are preserved.
- This prevents multiple large local models from competing for VRAM and system memory on 16 GB-class GPUs while a 100%-utilized GPU is already doing useful work.

## Sandbox fail-fast and verification gates

- If automatic sandbox preflight says isolation is required but returns `needs_setup`, `start_failed`, `manual_required`, `disabled` or another unready state, AgentNEO stops before the task graph/model pipeline.
- No generated-code host fallback is permitted.
- The response explicitly states that the sandbox was not created/tested instead of allowing a plausible report to be drafted.
- For prompts that request build/run/test/verify work, successful `sandbox_auto_run`/`sandbox_run_command` evidence is mandatory before final success.
- Non-zero sandbox command exit codes fail the verification gate.
- Automatic cleanup result is appended to tasks that explicitly ask AgentNEO to remove/destroy the temporary sandbox.

## Report ordering

- Writer nodes for code tasks now depend on Tester/Reviewer verification.
- Writer can no longer run at the start of a code job simply because the prompt contains the word `report`.

## Fast deterministic file operations

- Relative file-tool paths such as `sandbox_clock.py` now resolve under AgentNEO `WorkspaceRoot`.
- This prevents a relative path from accidentally resolving under the process/App directory and triggering a second outside-write permission wait after the initial workspace-write authorization.
- Tool events now record `duration_ms` and emit a `tool_slow` event when an operation exceeds the configured slow-tool warning threshold.

## Preserved behaviour

All v3.0.15 Autonomous Sandbox Orchestration, v3.0.14 Sandbox Lab, v3.0.13 Media Studio reliability, v3.0.11 hardened updater and earlier AgentNEO features remain preserved. No model weights or Windows VM/OS images are bundled.
