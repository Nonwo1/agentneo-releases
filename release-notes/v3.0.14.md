# AgentNEO v3.0.14 — Sandbox Lab / Autonomous Development Environment

AgentNEO v3.0.14 introduces **Sandbox Lab**, an isolated development and testing environment for AgentNEO's coding, testing, reviewing, PC Doctor and system-control workflows. The objective is to let AgentNEO create programs, acquire development tools, compile software, run tests and inspect generated artifacts without treating the user's normal Windows installation as the default execution environment.

## Sandbox Lab page

- Adds a dedicated **SANDBOX LAB** page and navigation entry.
- Displays Hyper-V, Windows Sandbox, VM console, base-image and credential readiness.
- Allows the user to register a user-owned Windows `.vhdx` base image, guest username and optional Hyper-V switch.
- Guest passwords are stored through AgentNEO's protected secret store rather than in normal settings JSON.
- Provides task creation controls for profile, network mode, persistence, RAM and CPU allocation.
- Provides task lifecycle controls: start, stop, open desktop, checkpoint, rollback, open task folder, destroy and refresh.
- Adds task tabs for overview, console, files/artifacts, checkpoints and reproducible recipe/audit data.

## Isolation backends

- **Windows Build Lab** — Hyper-V Generation 2 VM backed by a task-specific differencing VHDX whose parent is a user-provided Windows base VHDX.
- **Disposable Windows Build** — the same Hyper-V automation with an ephemeral task policy.
- **Quick Windows Sandbox** — `.wsb`-based disposable interactive testing plus one-shot automated build/test commands through a task-scoped startup runner.
- **Offline Analysis** — Windows Sandbox configuration with guest networking, clipboard, microphone, camera and printer redirection disabled; one-shot automated analysis commands remain available.
- AgentNEO does **not** bundle a Windows ISO, VHD/VHDX or Windows licence image.

## PowerShell Direct execution bridge

- Automated Hyper-V tasks use **PowerShell Direct** for guest command execution and host/guest file transfer. Quick/Offline Windows Sandbox tasks can execute a one-shot command by staging a task-scoped runner and collecting mapped Output/stdout/stderr/result files before the disposable sandbox shuts down.
- The VM does not need LAN/Internet networking for AgentNEO to run commands or move task files through this bridge.
- Task commands are executed inside the guest working directory, not through AgentNEO's normal host shell tool.
- The guest credential is supplied only to the local PowerShell Direct session and is not written into task recipes.

## Download and tool broker

- Sandbox tool downloads reuse the existing approved **AgentNEO downloader** and its normal progress UI.
- Downloaded installers/tools are staged into a task-specific sandbox `Tools` directory and are never automatically executed on the host.
- An optional expected SHA-256 can be supplied; a mismatch prevents the downloaded file from being staged into the sandbox.
- Download provenance and resulting SHA-256 are recorded in the sandbox task recipe/audit trail.
- `DOWNLOAD ONLY` is the default network policy for build tasks: the guest itself has no network adapter, while explicitly requested tools can be obtained through the AgentNEO host-side download broker and then transferred into the guest.

## Checkpoints, rollback and reproducibility

- Hyper-V tasks can create named checkpoints before risky installs or tests and restore them later.
- Each sandbox maintains `sandbox.recipe.json` with the selected environment and recorded actions.
- Destroying a task preserves its final recipe in the global Sandbox/Recipes directory.
- Persistent project sandboxes and disposable task sandboxes are separately selectable.

## Artifact promotion gate

- Generated output is first collected into the sandbox task's `Output` staging directory.
- AgentNEO calculates SHA-256 before promotion.
- On Windows, AgentNEO can inspect Authenticode state and request a Microsoft Defender custom scan before promotion.
- A promoted file is copied into `Workspace/SandboxExports/<task-id>` and is re-hashed after the copy; checksum mismatch aborts promotion.
- A sidecar `.agentneo-artifact.json` records source, destination, hash, inspection information and promotion time.

## Agent/tool routing

- Coder Fast, Coder Deep, Tester, Reviewer, System Control and PC Doctor receive the Sandbox Development Lab capability/skill and explicit sandbox permission scopes.
- Supervisor guidance now prefers Sandbox Lab for program creation, compilation, dependency/tool installation, generated-code execution and installer testing when a suitable sandbox backend is configured.
- Sandbox permissions are separate from host permissions. Ability to execute inside a sandbox does not imply permission to execute or modify the host.

## Preserved behaviour
