# AgentNEO v3.0.15 — Autonomous Sandbox Orchestration

AgentNEO v3.0.15 turns the v3.0.14 Sandbox Lab into an automatically orchestrated execution environment. A normal user prompt can now cause AgentNEO to decide that isolation is required, create or reuse the appropriate sandbox, share that environment across the agents working on the same task, acquire/stage required development tools, run builds/tests inside isolation, and safely retain or clean up the environment when the task finishes.

## Deterministic Sandbox Decision Engine

- Adds `SandboxDecisionEngine`, evaluated before the normal agent task graph starts.
- Classifies software build/run/test, dependency/tool acquisition, Windows installer/system testing, and suspicious/untrusted executable analysis as sandbox-required work.
- Pure source-code authoring can begin without a VM; execution isolation escalates later if an agent decides the code must be compiled, launched or tested.
- Existing Media Studio/ComfyUI generation is not unnecessarily wrapped in another VM unless the request also involves custom code, plugins or tool installation.
- Explicit PC Doctor requests that target the user's real PC remain under the normal host permission system rather than being silently redirected away from the machine that needs repair.

## Automatic Safe policy

- **AUTOMATIC SAFE** is the default autonomy mode.
- Routine sandbox create/reuse, execution, Workspace staging, dependency staging and safe lifecycle finalization can proceed without asking for every normal isolated action.
- Automatic Safe does **not** silently grant full/LAN guest networking, unrestricted host file bridges, host Administrator execution, or generated-code execution on the host.
- If isolation is required and no compatible Windows Sandbox/Hyper-V backend is ready, AgentNEO reports the setup requirement and blocks host fallback.
- `ASK FOR ELEVATED SANDBOX ACTIONS` and `MANUAL` remain selectable modes in Sandbox Lab.

## One shared sandbox per task

- The Supervisor creates/reuses the automatic sandbox before the task graph runs when the prompt requires it.
- Coder Fast, Coder Deep, Tester, Reviewer, System Control and PC Doctor attach to and reuse the same sandbox task rather than creating duplicate VMs.
- A run ID, optional project ID and stable reuse key are recorded in sandbox state/recipes.
- Project-persistent sandboxes can be reused across continued project work where appropriate.

## Dynamic execution escalation

- Host execution tools are guarded during sandbox-eligible development tasks.
- `run_shell`, generated-program launch, relevant PowerShell/service actions and software-related downloads can trigger a late sandbox decision.
- Generated-code build/run/test commands are redirected through `sandbox_auto_run` rather than the normal host shell.
- Software/tool downloads are redirected through `sandbox_auto_download`, which reuses the existing approved AgentNEO downloader and stages the result into the sandbox without executing it on the host.
- If an action cannot be safely mapped into the isolated backend, AgentNEO returns an explicit sandbox-required result instead of silently running the operation on the host.

## Workspace staging and guest readiness

- `sandbox_auto_stage_workspace` copies only content under AgentNEO `WorkspaceRoot` into the task's writable Work area.
- Arbitrary host paths still require the explicit manual sandbox host-bridge permission.
- Hyper-V automatic execution/staging waits for a PowerShell Direct readiness probe before sending commands or files to the guest.

## Lifecycle and artifact safety

- Failed automatic sandboxes are retained for debugging.
- Project sandboxes are retained for continued work.
- Successful tasks with files still present in sandbox Output are retained until those artifacts are reviewed/promoted.
- Only successful **empty ephemeral** automatic sandboxes are eligible for automatic destruction when cleanup is enabled.
- Existing v3.0.14 artifact SHA-256, Authenticode/Defender inspection and provenance promotion controls remain unchanged.

## Agent skills and permissions

- Adds the **Autonomous Sandbox Orchestration** built-in skill package.
- Adds separate `sandbox_auto_create`, `sandbox_auto_execute`, `sandbox_auto_bridge` and `sandbox_auto_manage` scopes.
- Automatic sandbox permissions remain distinct from host execution/admin permissions.

## Preserved behaviour

All v3.0.14 Sandbox Lab backends and safety controls are retained, including Hyper-V differencing VHDX, PowerShell Direct, Windows Sandbox quick/offline profiles, task recipes, checkpoints/rollback, the approved AgentNEO download broker, and verified artifact promotion. v3.0.13 Media Studio reliability fixes and earlier updater, PC Doctor, privacy, Whisper and Neural Galaxy work are also preserved.
